# P-001 北極星與不做清單

## 當前情境

- 只服務我自己的遊戲：目前一款 3D 遊戲把 LDtk 當版面的唯一來源（碰撞、不可去區域、高度、傳送點、出生點、零件位置），地形由地圖長出來，零件在 Blender 做。
- 未來可能做 2D 平台、俯視 3/4 遊戲，所以不綁死某一款遊戲的層名。
- 手動在 LDtk 擺版面慢；想讓 AI agent 從規則生成整張場景地圖，再透過對話一起微調。

## 決策

**北極星：**讓我和 AI agent 從一段規則描述開始，透過對話生成並微調整張 LDtk 地圖；地圖照一套固定的分層慣例寫出（IntGrid 區域與 Entity 位置），LDtk 打得開，引擎照慣例就能長出關卡；每一步都輸出 PNG 預覽，讓我在任何地方透過 agent 看到成果。

驗證北極星時判斷過的工作：

| 工作 | 種類 |
|---|---|
| 與 AI agent 一起設計地圖（規則生成、對話微調） | 目的 |
| 地圖可以直接用在遊戲：版面，或引擎直接長出的完整地圖 | 目的 |
| 輸出 PNG，透過 agent 看成果，遠端也好用 | 目的 |
| 固定的分層慣例，讓引擎容易串接 | 目的 |
| 現在就支援 2D 平台遊戲的專用層 | 延伸 |
| 網頁版編輯介面 | 延伸 |
| 地圖擺 tileset 圖塊美術 | 延伸（記在 backlog） |

**不做清單：**跟北極星相關性極低、已經判定不做的具體項目。

- 服務其他 LDtk 使用者：不處理別人的 LDtk 設定相容、不寫推廣文件。
- 引擎端的匯入程式：Blender、遊戲引擎怎麼讀、怎麼長地形，寫在遊戲專案裡。
- 其他地圖格式：不讀寫 Tiled (.tmx) 或其他編輯器的格式。
- 遊戲執行時即時生成：地圖在開發時生成並存成檔，不做成遊戲執行中動態生成的函式庫。

## 三個月後的影響

- 對話生成、微調、PNG 預覽、分層慣例排在最前面；圖塊美術、網頁介面、2D 平台專用層會被排進「待排」。
- 想公開給別人用、或要寫引擎匯入程式時，要先把那一項從不做清單拿掉。
