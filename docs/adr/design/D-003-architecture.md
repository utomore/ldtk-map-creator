# D-003 核心函式庫加兩個薄入口（core、mcp、cli）

## 當前情境

- 入口有兩種：MCP（給 Claude Code）與 CLI（除錯、測試用）；兩者做的事一樣。
- 業務規則中等：生成規則、LDtk 的一致性（`uid`、`iid`、`__` 欄位）、之後的分層慣例。
- 一個人加 AI agent 開發，不移交；架構要從簡。

## 選擇

| 選項 | 適合 | 代價 |
|---|---|---|
| 型錄 `py-ports-adapters`（四層、六條依賴契約） | 多人開發、業務規則多、要移交 | 適用條件只符合一半；入口是 FastAPI 加 Typer，MCP 不在它的檢查範圍；每個功能動四處 |
| 核心函式庫加兩個薄入口 | 一個人、要從簡、主要入口是 MCP | 型錄沒有這一格，沒有依賴契約與檢查腳本，規則只靠審查守 |
| 直接手改 `.ldtk`，不寫工具 | 零成本 | 容易改壞檔、吃 token、看不到結果 |

## 決策

- 採用核心函式庫加兩個薄入口：`core/`、`mcp/`、`cli/`。
- 型錄沒有這一格：這裡只記決策，不附依賴契約與檢查腳本。
- 怎麼切、依賴方向、law 住哪寫在 P-003。

## 三個月後的影響

- 新增一個功能只動 `core/` 加兩個入口各一個轉呼叫。
- 依賴方向沒有機器擋，靠 agent 自審；之後要加檢查另開 issue。
- 專案長大要遷到 ports and adapters 時，`core/` 拆成 `domains/` 加 `application/`，代價中等。
