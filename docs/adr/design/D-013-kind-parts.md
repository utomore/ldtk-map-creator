# D-013 圖格種類可以帶零件：生成時在區域中心擺 Part

## 當前情境

- 規則檔寫 `kind = "house"`，生成只寫下「地面是泥土、碰撞是牆」；「這是房子」的意思沒進地圖，引擎畫不出房子，也不該從一圈牆去猜（#51）。
- 照 D-011，模型靠 `Part` entity 擺；之前每間房子都要另寫一行 `[[entity]]`。
- 情境：村莊有十間房子。

## 選擇

| 選項 | 適合 | 代價 |
|---|---|---|
| 圖格種類可以帶零件，生成時自動擺（選中） | 十間房子不用寫十行；「這是房子」不會在生成時掉 | 規則檔格式多兩個欄位；擺的位置與方向是固定的規則 |
| 每間各寫一行 `[[entity]]` 的 Part | 不用改工具；每個可以個別調 | 規則檔重複；漏寫就畫不出來 |
| 引擎從碰撞與地面猜 | 地圖不用多寫 | 一圈牆可以是房子、石頭或圍欄，猜不準 |

## 決策

- 圖格種類多兩個選填欄位：`part`（零件名稱，不是空白的字串）、`yaw`（數字，預設 0）；只寫 `yaw` 沒寫 `part` 是錯。
  - 例：`house = { ground = "dirt", collision = "wall", part = "house", yaw = 90 }`。
- 生成時，這個種類的每個區域在它的 `.center` 擺一個 `Part`，`part`、`yaw` 照種類；iid 由 seed 加元素名稱推出，重新生成引用不斷。
- 只有區域能帶零件；路徑用了帶零件的種類，讀規則檔就報錯。
- 擺的格跟別的 entity 撞到時丟 SceneError，訊息開頭是區域的 `.kind`。
- 要個別調位置或方向的，照舊用 `[[entity]]` 寫 Part，種類就不要帶零件。

## 三個月後的影響

- 地圖上看得到的東西，規則檔裡都說得出來：地形寫在種類的層，模型寫在種類的零件或 `[[entity]]`。
- 一塊區域要擺好幾個零件、或擺在門口而不是中心時，再加寫法；不推翻這份。
