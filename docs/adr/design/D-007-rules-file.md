# D-007 規則檔用宣告式：地圖上每一塊東西寫成一個有名字的元素

## 當前情境

- 北極星：從一段規則描述開始生成，再在對話裡微調。
- 微調時用名字指東西，例如「把 house_2 移到廣場東邊」。
- 原型（村莊：廣場、三間房、一條路、出生點）：加一行 `side = "east"`，只有 house_2 移動。
- 引擎與 LDtk 的 Entity Ref 用 iid 指向 entity；重新生成之後，引用要接得上（#13）。

## 選擇

| 選項 | 適合 | 代價 |
|---|---|---|
| 參數式：選生成器、調參數 | 先做出來最快 | 每種地圖一個生成器；規則對不上地圖上的東西 |
| 宣告式：每塊東西一個元素，寫在哪、靠近誰、連到哪 | 微調對得上規則的一行 | 配置器比較難寫；規則比參數式長 |
| 混合：宣告式加上掛在元素上的小生成器 | 最有彈性 | 規則分兩層 |
| iid 由 seed 加元素名稱推出（uuid5） | 重新生成後 iid 不變，引用接得上 | 改了元素的名字，iid 就變 |
| iid 保持隨機，比對生成結果時不看 iid | 最簡單 | 每次重新生成，所有 Entity Ref 都斷一次 |

## 決策

- `<名>.rules.toml` 用宣告式。
- M2 只做三種元素：`[[area]]`、`[[path]]`、`[[entity]]`；每個元素有唯一的 `name`。
- 每個元素用 seed 加自己的名字當亂數種子；改一個元素，其他元素的亂數不受影響。
- 生成器產生的 iid 由 seed 加元素名稱推出（uuid5）；同規則同 seed，生成結果連 iid 都相同。
- 用工具手動擺的 entity，iid 照舊隨機。
- 之後要加小生成器，就在元素上加欄位，不推翻宣告式。

## 三個月後的影響

- 沒有固定位置的元素照檔案順序排；固定一個元素，可能把排在後面的擠走。
- 預覽圖要標出元素名稱，微調時才叫得出名字。
- 「種類對應哪個 IntGrid 值」由分層慣例管：圖格種類寫進哪幾層，見 D-011。
- 元素改名等於換一個元素：位置的亂數與 iid 都會變。
