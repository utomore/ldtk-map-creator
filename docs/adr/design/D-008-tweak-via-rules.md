# D-008 從規則生成的場景地圖，微調一律改規則檔再重新生成

## 當前情境

- 地圖有兩種改法：改規則再重新生成；直接改地圖（在 LDtk 手動改，或用 M1 的操作）。
- 重新生成只看規則檔，直接改過的地方會被蓋掉。
- 例子：在 LDtk 手動畫一棵樹，隔天在規則加一間房子並重新生成，那棵樹就不見了。
- 我很少在 LDtk 手動改，大多透過對話改。

## 選擇

| 選項 | 適合 | 代價 |
|---|---|---|
| 規則是唯一的來源：微調寫進規則檔再重新生成；有直接改過的地方就先停下來 | 重新生成後微調都還在，不會在不知情時丟東西 | 規則檔變長；零碎細節也要寫成元素 |
| 直接改地圖；重新生成會蓋掉，事先警告 | 最簡單 | 每次改規則都可能丟微調，要自己記得改過哪裡 |
| 微調記成紀錄，重新生成後重播 | 手動改也不丟 | 要設計紀錄格式與衝突規則，跟從簡衝突（backlog） |

## 決策

- 從規則生成的場景地圖，規則檔是唯一的來源：對話裡的微調，agent 改規則檔再重新生成。
- 零碎的細節（例如一棵樹）寫成一個元素，例如 1×1、給定位置的 `[[area]]`。
- 重新生成前，先比對地圖跟上次生成的結果：
  - 一樣：照新規則重新生成。
  - 不一樣（有人直接改過）：預設拒絕，列出差異；開發者明確要求才覆蓋。
- 沒有規則檔的場景地圖，照舊用 M1 的操作直接改。

## 三個月後的影響

- 上次生成的結果記在 `<名>.generated.json`（D-002）：只記生成負責寫的內容（level 大小、IntGrid、entity 的 iid、定義與位置），在 LDtk 打開再存一次不算改過。
- 沒有生成紀錄的場景地圖（例如用 M1 的操作建的）加了規則檔，第一次生成也要帶 force。
- 常在 LDtk 手動改的話，每次都會被擋下來；到時回頭考慮重播（backlog「微調紀錄與重播」）。
