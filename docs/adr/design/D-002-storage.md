# D-002 一個場景地圖一組檔，放在使用者指定的路徑

## 當前情境

- 要存的是場景地圖：一個 LDtk 專案，裡面有多個 level（例如村莊外圍幾塊，加上每間房子的內部）。
- 生成要能重現：同一份規則加同一個 seed 要得到同樣的結果；每一步要留 PNG 給我看。
- 只有我一個人用，檔案跟著遊戲專案走。

## 選擇

| 選項 | 適合 | 代價 |
|---|---|---|
| 工具不管存放，規則只在對話裡 | 最簡單 | 對話結束規則就沒了，無法重現 |
| 一個場景地圖一組檔，含規則檔與 seed | 要重現、要看得到改了什麼 | 多一個檔；「重生」和「已做的微調」會衝突，要另外設計 |
| 再加微調紀錄，可重播與 undo | 改規則不丟微調 | 範圍大，跟從簡衝突；記在 backlog |
| 存法：一律拆開 | 場景大、git diff 只看到改到的 level | 不支援單檔的載入器 |
| 存法：一律單檔 | 載入器最簡單 | 場景大時檔案很大 |
| 存法：兩種都支援，新建預設拆開 | 不同遊戲可能用不同載入器 | 兩條路徑都要測 |

## 決策

- 一個場景地圖一組檔，放在使用者指定的路徑（例如遊戲專案的 `maps/`）：
  - `<名>.ldtk`：主檔。
  - `<名>/`：子資料夾，每個 level 一個 `.ldtkl`，拆開存時才有。
  - `<名>.rules.toml`：規則檔，含 seed。
  - `<名>.generated.json`：生成紀錄，記下上次生成的結果，重新生成前拿來比對（D-008）；從規則生成過才有。
  - `previews/<名>/`：每個 level 一張 `<level>.png`，加一張世界總覽 `world-overview.png`（名稱有 `-`，不會跟 level 撞名）；多個場景地圖放同一個資料夾時不會撞名。
- 兩種存法都支援：讀 `externalLevels` 決定怎麼寫；新建場景地圖時預設拆開；規則檔頂層寫了 `split` 就照它，不看磁碟上原本怎麼存（D-014）。
- 這個 repo 只放工具本身與範例場景地圖。

## 三個月後的影響

- 拆開存時，引擎的載入器要照 `externalRelPath` 讀 `.ldtkl`；常見的 LDtk 載入器會處理，自寫的要補。
- 改規則重生會蓋掉已做的微調：微調一律改規則檔，見 D-008。
- 拆開存的格式（LDtk 1.5.3 實測，#3）：
  - 主檔跟單檔只差 `externalLevels: true`；每個 level 的 `layerInstances` 是 `null`，`externalRelPath` 是相對主檔的路徑，例如 `split/Level_0.ldtkl`。
  - `.ldtkl` 是完整的 level 物件，多一個 `__header__`，裡面的 `externalRelPath` 是 `null`。
  - 子資料夾名稱跟主檔同名（不含副檔名）。
